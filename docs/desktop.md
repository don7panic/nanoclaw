# Nanoclaw Desktop App（面向非技术用户）重构版设计方案

## 一、方案摘要（基于已确认决策）

- 目标：让非技术用户“一次安装、向导配置、稳定运行”完成系统初始化。
- 已锁定决策：
  - 平台优先：`macOS`
  - 进程模式：Desktop App `spawn` 本地 `nanoclaw` 子进程
  - 依赖策略：用户侧尽量零依赖（不要求命令行/开发环境）
  - 容器策略：**不引入 container**（默认与 MVP 阶段）
- 核心原则：少步骤、强默认、可恢复、可诊断。

---

## 二、产品目标与范围

## 1) 成功标准
- 非技术用户可在 5–10 分钟内完成首次初始化。
- 初始化失败可在 App 内定位并修复（无需终端）。
- 用户不需要理解命令行、端口、配置文件结构。

## 2) MVP 范围（in scope）
- 初始化向导（步骤化）
- 预检查（依赖/权限/端口/文件）
- 配置采集（表单 + 默认值）
- `nanoclaw` 启动与健康检查
- 错误提示与一键重试
- 日志与诊断包导出

## 3) 非目标（out of scope）
- 复杂集群管理
- 远程多节点编排
- 容器编排与镜像管理

---

## 三、总体架构（无容器、本地子进程）

## 1) 模块分层

- **UI 层（Renderer）**
  - 向导页面、状态页、错误修复页、设置页
- **应用后端层（Desktop Backend）**
  - `InitOrchestrator`：初始化步骤编排
  - `ProcessSupervisor`：子进程生命周期管理
  - `ConfigService`：配置读写、模板渲染、版本迁移
  - `HealthService`：健康检查与可用性判定
  - `DiagnosticService`：日志汇总与导出
- **核心服务层（nanoclaw binary）**
  - 由本地进程提供业务 API（HTTP/Socket）

## 2) 关键运行路径
1. App 启动 → 执行预检查  
2. 用户完成向导表单 → 生成配置  
3. `ProcessSupervisor.start()` 启动 `nanoclaw`  
4. `HealthService` 轮询健康状态  
5. 成功进入“运行中”仪表页；失败进入“修复引导页”

---

## 四、依赖设计（面向非技术用户）

## 1) 用户侧必须依赖（最小）
- macOS（支持版本由发布策略定义）
- 用户目录可读写权限
- （可选）网络，仅用于自动更新或在线帮助

## 2) App 内置依赖（必须）
- `nanoclaw` macOS 可执行文件
- 默认配置模板与字段定义
- 错误码-文案映射表
- 健康检查与诊断逻辑

## 3) 明确不需要
- Docker / Colima / 容器运行时
- 用户手工安装 Node/Go/Rust/Python
- 终端命令参与初始化流程

---

## 五、核心组件设计（决策完成）

## 1) InitOrchestrator（初始化编排器）
- 职责：执行固定状态机  
  `idle -> precheck -> collect_config -> apply_config -> start_service -> verify -> done/failed`
- 要求：
  - 每步有标准输出：`status`, `errorCode`, `userMessage`, `actionHint`
  - 支持断点恢复（从失败步骤重试）

## 2) ProcessSupervisor（进程监管器）
- 接口（建议）：
  - `start(configPath): StartResult`
  - `stop(): StopResult`
  - `restart(): RestartResult`
  - `status(): ProcessStatus`
  - `tailLogs(limit): LogChunk`
- 实现约束：
  - 保存 PID 与启动时间
  - 采集 stdout/stderr 到本地日志
  - 启动超时与崩溃自动检测
  - 防重复启动（幂等）

## 3) ConfigService（配置服务）
- 输入：向导表单数据
- 输出：结构化配置文件（写入 App 数据目录）
- 约束：
  - 强校验（格式/范围/必填）
  - 变更备份（失败可回滚上一版本）
  - 敏感字段加密存储（系统 keychain）

## 4) HealthService（健康服务）
- 检查项：
  - 进程存在
  - 端口监听
  - 健康接口返回（如 `/health`）
- 判定策略：
  - 连续 N 次成功判定“可用”
  - 连续 N 次失败触发“异常恢复建议”

## 5) DiagnosticService（诊断服务）
- 导出内容：
  - 启动日志、错误码、环境信息、配置脱敏快照
- 用途：
  - 用户一键复制/导出给支持团队

---

## 六、用户流程（简洁化设计）

## 1) 首次使用（最多 4 屏）
1. 欢迎页（说明只需几分钟）  
2. 环境检查（自动）  
3. 配置填写（少字段 + 默认值）  
4. 一键启动（显示进度与结果）

## 2) 失败恢复流程
- 明确错误类型（可理解文案）
- 提供单一推荐动作（“一键修复”或“重新填写”）
- 保留“查看详情”入口，但默认折叠技术信息

## 3) 日常使用流程
- 首页仅显示：运行状态、最后检查时间、重启按钮、导出诊断

---

## 七、数据与接口定义（新增公共类型）

- `InitState`：初始化阶段枚举
- `InitStepResult`：步骤执行结果
- `ProcessStatus`：`stopped | starting | running | unhealthy | crashed`
- `AppErrorCode`：面向用户的稳定错误码
- `UserFacingError`：`title + message + suggestedAction`

说明：上述类型作为 Desktop 内部契约与 UI 渲染依据，保证错误处理一致、可本地化。

---

## 八、安全与稳定性要求

- 命令执行白名单化，禁止拼接不受控参数
- 敏感日志脱敏（密码/token/密钥）
- 仅在必要时请求系统权限
- 启动失败不崩 App：服务失败与 UI 生命周期解耦
- 所有关键操作可重试、可取消、可恢复

---

## 九、测试与验收（MVP）

## 1) 测试场景
- 正常初始化：新安装首次成功
- 配置错误：字段非法可阻断并提示
- 端口占用：检测并给修复路径
- 进程崩溃：状态切换正确并可重启
- 健康检查超时：触发异常态与建议动作
- 日志导出：内容完整且脱敏有效

## 2) 验收指标
- 首次安装初始化成功率 ≥ 90%
- 失败后可自助恢复率 ≥ 80%
- 用户平均初始化步骤 ≤ 4 个主步骤
- 主流程无终端依赖（0 CLI 手动步骤）

## 十、发布与演进路线

## Phase 1（MVP）
- 完成向导、配置写入、spawn 启动、健康检查、重试与日志导出

## Phase 2（稳定性）
- 增强错误分类、回滚策略、自动恢复与诊断体验

## Phase 3（产品化）
- 自动更新、配置模板、多语言支持、可观测性增强

---

## 十一、默认假设（已锁定）

- 当前只保证 macOS 主平台体验
- `nanoclaw` 可通过本地可执行文件直接运行
- 不引入容器能力到普通用户路径
- 以“少配置高成功率”为优先，非高级选项默认隐藏
